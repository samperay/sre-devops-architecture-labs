# Progress

Status is a record of evidence, not a goal statement. All ten projects start at `NOT STARTED`. No milestone has been implemented, reviewed, or merged.

## States

| State | Meaning |
| --- | --- |
| `NOT STARTED` | No implementation or study evidence yet. |
| `IN PROGRESS` | Work is underway and not yet merged to `master`. |
| `LAB COMPLETED` | The milestone PR was reviewed, tested, and merged. The lab runs as described. |
| `UNDERSTOOD` | You can explain the design, data flow, and failure modes without reading the diff. |
| `APPLIED` | You have used the idea again: a later milestone, a failure exercise, or a written trade-off that depends on it. |
| `ARCHITECT READY` | You can defend the design, troubleshoot it, operate it, and communicate the trade-offs to a reviewer. |

## Rules

- A milestone is implementation-complete only after its pull request is reviewed, tested, and merged into `master`.
- A merged pull request does not automatically mean `UNDERSTOOD` or `ARCHITECT READY`.
- Architecture readiness requires demonstrated design reasoning, troubleshooting, operational understanding, and communication.
- Progress updates must be supported by actual evidence: a merged PR link, test output, a written failure note, or a design discussion. Do not mark a state because the work is planned.
